# Настройка сервера для индексации ИИ-системами (LLMO)

Инструкция для администратора хостинга/домена. Сайт — статический
(HTML/CSS/JS без сборщика), сейчас размещён на Timeweb (shared-хостинг),
домен: **тамбовавтосервис.рф** (punycode: `xn--80aacebauz3avdzlebh.xn--p1ai`).

Файлы `robots.txt`, `sitemap.xml` и JSON-LD-разметка в `<head>` уже
настроены в коде сайта (см. папку `STO/`) — эта инструкция про то, что
нужно сделать **на уровне сервера/панели хостинга/личных кабинетов**,
а не в коде.

---

## 1. GeoIP-блокировка — открыть доступ ботам ИИ

Боты OpenAI (`GPTBot`, `ChatGPT-User`, `OAI-SearchBot`), Anthropic
(`ClaudeBot`, `Claude-Web`), Google (`Google-Extended`) и Bing
(`Bingbot`) физически приходят с IP-адресов в США/Европе. Если на
сервере включена геоблокировка зарубежных IP (защита от спама/DDoS),
эти боты **не смогут достучаться до сайта вообще**, независимо от того,
что написано в `robots.txt` — geoblocking отсекает соединение раньше,
чем сервер вообще посмотрит на User-Agent.

**Важно:** `robots.txt` только просит бота "не заходи" или "заходи" —
это джентльменское соглашение. GeoIP/DDoS-защита физически рвёт TCP-
соединение до того, как запрос доходит до сайта. Даже идеальный
`robots.txt` не поможет, если боты блокируются на уровне сети.

### Если хостинг — обычный shared-хостинг Timeweb (как сейчас)

На базовом shared-хостинге Timeweb (тарифы без VPS/root-доступа) нет
своего Nginx-конфига, который можно редактировать напрямую. Что делать:

1. Зайти в панель Timeweb → **Хостинг → [ваш сайт] → Безопасность** (или
   раздел «Защита от ботов» / «WAF», если такой есть на вашем тарифе).
2. Проверить, включена ли там геоблокировка/защита от иностранных IP.
   Если да — добавить перечисленные выше имена ботов в исключения
   (allow-list), либо написать в поддержку Timeweb с просьбой не
   блокировать эти User-Agent'ы для вашего домена.
3. Если сайт стоит **за Cloudflare или DDoS-Guard** отдельно от
   Timeweb — см. ниже.

### Если используется Cloudflare

1. **Security → WAF → Custom rules** → создать правило:
   `(cf.client.bot) and not (http.user_agent contains "GPTBot" or http.user_agent contains "ClaudeBot" or http.user_agent contains "Google-Extended" or http.user_agent contains "Bingbot" or http.user_agent contains "ChatGPT-User" or http.user_agent contains "PerplexityBot")`
   → действие **Skip** (пропустить) для этих User-Agent при остальных
   правилах блокировки по гео.
2. Проще: в **Security → Bots** отключить блокировку "AI Crawlers"
   (Cloudflare с 2024 года даёт отдельный переключатель "Block AI
   Bots" — убедиться, что он **выключен**, если хотите, чтобы ИИ
   индексировали сайт).

### Если используется DDoS-Guard

1. Личный кабинет DDoS-Guard → **Настройки домена → Правила фильтрации**.
2. Добавить исключение по User-Agent (или по ASN, если DDoS-Guard
   поддерживает whitelisting по подсети) для ботов выше.
3. Если DDoS-Guard настроен через партнёра/провайдера — уточнить
   формат правил у их поддержки, интерфейсы отличаются.

### Если это VPS/выделенный сервер с Nginx (на будущее)

Готовый сниппет для `nginx.conf` / `default.conf` (если появится
собственный сервер вместо shared-хостинга):

```nginx
map $http_user_agent $is_ai_bot {
    default 0;
    "~*GPTBot"              1;
    "~*ChatGPT-User"        1;
    "~*OAI-SearchBot"       1;
    "~*ClaudeBot"           1;
    "~*Claude-Web"          1;
    "~*Anthropic-AI"        1;
    "~*Google-Extended"     1;
    "~*Bingbot"             1;
    "~*PerplexityBot"       1;
    "~*YandexBot"           1;
}

server {
    # ... остальной конфиг ...

    # Пропускаем ИИ-ботов мимо любых geoip/deny-правил
    if ($is_ai_bot) {
        set $skip_geoblock 1;
    }

    location / {
        # пример: если используется geoip_country + deny,
        # сначала проверяем $skip_geoblock
        if ($skip_geoblock = 1) {
            break;
        }
        # ... остальная geoip-логика ...
    }
}
```

## 2. Punycode и SSL

**Важное уточнение, чтобы не тратить время зря:** `тамбовавтосервис.рф`
и `xn--80aacebauz3avdzlebh.xn--p1ai` — это **один и тот же домен**, а
не два разных. Punycode — это просто ASCII-кодировка кириллического
имени, которую браузеры и серверы используют "под капотом". Никакого
отдельного редиректа между ними настраивать не нужно — браузер сам
конвертирует `тамбовавтосервис.рф` в punycode перед тем, как
обратиться к DNS/серверу. Если вбить в адресную строку любую из двух
форм — попадёте на один и тот же сайт при условии, что SSL и DNS
настроены на сам домен (неважно, в какой записи он указан).

Шаги:

1. **DNS** — домен должен указывать (A-записью или NS-делегированием)
   на сервер Timeweb. Уже проверено: домен резолвится на
   `92.53.96.132` (реальный сервер Timeweb) — это готово.
2. **Панель Timeweb → Домены и SSL** → найти домен (Timeweb покажет его
   в любой из форм записи, кириллицей или punycode — это не имеет
   значения) → **Выпустить SSL-сертификат** (обычно бесплатный Let's
   Encrypt, доступен в один клик).
3. Проверить, что сертификат выпущен именно на punycode-имя
   (`xn--80aacebauz3avdzlebh.xn--p1ai`) — Let's Encrypt всегда работает
   с ASCII-именами, это нормально и ожидаемо, кириллическое имя в
   сертификате никогда не фигурирует буквально.
4. После выпуска сертификата — включить принудительный редирект с
   `http://` на `https://` (обычно тоже тумблер в панели Timeweb, либо
   `.htaccess`/настройка в разделе "Домены").

## 3. Чек-лист: подключение личных кабинетов вебмастеров

| Система | Портал | Статус / примечание |
|---|---|---|
| **Яндекс.Вебмастер** (нужен для Алисы / YandexGPT / Нейро) | webmaster.yandex.ru | Добавить сайт → подтвердить владение (мета-тег или файл) → **Индексирование → Файлы Sitemap** → добавить `https://xn--80aacebauz3avdzlebh.xn--p1ai/sitemap.xml` |
| **Bing Webmaster Tools** (критично: индекс Bing частично используется ChatGPT для веб-поиска) | bing.com/webmasters | Можно импортировать сайт прямо из Google Search Console (кнопка в интерфейсе) или добавить вручную и подтвердить владение. Затем **Sitemaps → Submit sitemap** |
| **Google Search Console** (для Gemini / Google AI Overviews) | search.google.com/search-console | Добавить домен-ресурс, подтвердить через DNS TXT-запись у регистратора домена → **Sitemaps → Добавить sitemap** |
| **Сбер / GigaChat** | — | На момент подготовки этой инструкции у Сбера **нет широко известного публичного вебмастер-кабинета** для отправки sitemap (в отличие от Яндекса/Bing/Google). GigaChat, судя по всему, полагается на собственный краулинг открытого веба + сигналы из `robots.txt`. Явных публичных self-service порталов нет — если появятся, добавить сюда отдельным пунктом. Что можно сделать уже сейчас: `robots.txt` уже разрешает всё (`User-agent: *` → `Allow: /`), плюс явные записи для `GigaBot`/`SberBot` на случай, если Сбер их когда-нибудь начнёт использовать. |

**После добавления в любой кабинет:** не ждите мгновенной индексации —
у всех систем это может занять от нескольких часов до нескольких
недель. Если Яндекс.Вебмастер (или любой другой кабинет) ранее
показывал ошибку DNS — сначала убедитесь, что DNS полностью
распространился (см. раздел 2), и только потом добавляйте sitemap
заново.
